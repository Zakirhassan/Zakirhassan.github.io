What I Learned Building AI Agents as a Software Engineer from Kanpur

By Mohd Zakir Hassan · Kanpur, India · 20 November 2026

I'm Mohd Zakir Hassan, a Tech Lead and software engineer from Kanpur. Over the last year I've spent most of my evenings building AI agents: small programs that take a goal, decide what steps to take, call tools, and keep going until the job is done. I document this work as Build With Zakir. Here's what I've learned so far.

1. Start with a boring, real problem. My best agents weren't flashy. One drafts daily job posts for a local jobs page. Another turns a voice note into an expense entry. A clear input, a clear output, and a person who actually needs the result. That's the whole recipe.

2. Tools matter more than prompts. A well-designed tool (search, read a file, post to an API) with a clear name and description does more for reliability than a long prompt. When an agent fails, the fix is usually a better tool, not more instructions.

3. Keep a human in the loop for anything public. My agents draft and I approve. Anything that posts, pays, or sends a message waits for a yes. It's slower, but it's the reason I trust them.

4. Log everything. Every step an agent takes goes into a log. When something goes wrong, the log tells you whether the model misunderstood, a tool failed, or the input was bad.

5. Ship small, then expand. Get one task working end to end before you add the second. Most "agent frameworks" fail because they try to do ten things on day one.

You don't need to be in Bengaluru or San Francisco to build with AI. I build from Kanpur and New Delhi with a laptop and a lot of curiosity. If you're starting out, pick one annoying task in your week and try to automate it this weekend.
