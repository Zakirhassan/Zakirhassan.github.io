6 Years of React: Architecture Lessons That Actually Scale

By Mohd Zakir Hassan · Kanpur, India · 19 November 2026

I'm Mohd Zakir Hassan, a Tech Lead with 6+ years of building React applications used by thousands of people. These are the habits that have held up as teams and products grew.

Components should do one thing. If a component fetches data, formats it, and renders a complex UI, split it. Containers handle data; presentational components handle looks.

Make state predictable. Keep server state (data from APIs) separate from UI state (is this modal open?). Tools like React Query for server state and plain React state for UI cover most needs before you reach for a global store.

Design your folder structure around features, not file types. /features/billing/ beats /components, /hooks, /utils once the app gets big.

Measure before you optimise. Use the React Profiler and real user metrics. Most slowness comes from a few heavy re-renders or oversized bundles, not from everywhere.

Secure by default. Short-lived JWTs, refresh tokens in httpOnly cookies, and role checks on the server, never only in the UI.

Reviews are where architecture lives. As a Tech Lead, the biggest lever I have is code review: small, frequent, and focused on structure over style.
