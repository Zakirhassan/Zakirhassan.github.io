Software Developer in Kanpur — Mohd Zakir Hassan

I'm Mohd Zakir Hassan, a software developer in Kanpur and a Tech Lead with 6+ years of experience building web applications. Who I am

I started in 2019 with a Java internship, and since 2020 I've been building production web applications at Truminds Software Systems, where I'm now a Tech Lead. I hold an MCA from Jamia Millia Islamia. My time is split between Kanpur and New Delhi, and I'm happy to be a tech lead in Kanpur: it shows freshers here that serious engineering work doesn't require relocating first.

As a software engineer in Kanpur I'm also a full stack developer in the practical sense. I'm most comfortable on the React side, but I've spent enough time on APIs, authentication and data modelling to care about the whole system, not just the screen.

What I work with

React and Next.js. As a React developer in Kanpur, most of my day is component design, state management and performance. As a Next.js developer in Kanpur, I use server rendering and the App Router where they help users, and keep routes thin so the real logic lives in testable feature modules.

Node.js and TypeScript. Node.js is my default backend. As a Node.js developer in Kanpur I build REST APIs with Express, validate everything at the boundary and lean on TypeScript so refactors stay safe.

The MERN stack. I've built with MongoDB, Express, React and Node.js together for years, so as a MERN stack developer in Kanpur I'm comfortable owning a feature from the database to the browser. Day to day that makes me a web developer in Kanpur who treats the frontend and backend as one product.

AI agents and automation. Over the last year I've been building agents: programs that take a goal, call tools and loop until the job is done. As an AI developer in Kanpur and, increasingly, an AI automation engineer in Kanpur, I focus on the unglamorous parts: tool design, logging, step limits and human approval for anything public. I wrote about this in Building AI Agents with Node.js.

How I approach architecture, performance and security

Architecture. I organise code around features, not file types, and keep server state (data from APIs) separate from UI state. Components do one job. The details are in my playbook for structuring large React and Next.js apps.

Performance. I measure before I optimise. The React Profiler and real user metrics usually point at a handful of heavy re-renders or an oversized bundle, and fixing those beats scattered micro-optimisations.

Security. Short-lived JWTs, refresh tokens in httpOnly cookies and role checks on the server, never only in the UI. The same applies to AI tools: an agent should only be able to do what its tools allow.

Leadership. My biggest lever as a tech lead is code review: small, frequent and focused on structure over style.

The Kanpur tech scene

Kanpur is best known for IIT Kanpur and its industrial history, and I won't pretend it has a Bengaluru-sized startup scene. What it has is plenty of talented students and engineers, and remote and hybrid work has made your postcode matter far less than your portfolio. The thing Kanpur often lacks is visibility, which is a big reason I build in public and write things down.

If you're early in your career here, my advice is simple: go deep on one stack, ship real projects, and make yourself easy to find. I've put the longer version in a practical guide for freshers.
